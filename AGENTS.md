# Release versions and notes

- For each substantive user-requested release, update the Toolkit footer version in the shared app shell and Email Sender footer. Use the user's specified version; otherwise increment the minor version once per release-sized request. Do not bump again for follow-up fixes within the same unreleased change.
- Keep user-facing release notes only in `version-history/index.html`. Do not add expanded histories to individual tool pages or add Version History to primary navigation. Link to it from Settings and page footers.
- Add an entry describing the actual change, using only known dates and history. Include the resulting version and a concise, copyable release note in the final response.
- These updates do not authorize committing or pushing. Only commit or push when explicitly requested.
