# SSA saved-application development extension

This separate Manifest V3 package opens `https://secure.ssa.gov/iClaim/dib` in a new tab from the Intake Assistant. The employee must review the Terms of Service and click Next manually. The Toolkit bridge sends only the one unique, ready SSN and a temporary employee-entered re-entry number; it never sends an Intake Checker profile, source text, or application answers. Do not enter real client information during development tests.

Install in Chrome from `chrome://extensions` → Developer mode → Load unpacked → this folder. It has a different extension ID from the synthetic practice extension and can be installed alongside it. Reload here after changes. Use a test browser profile for development. Staff distribution and browser policy approval are separate decisions.

The permissions are `activeTab`, `scripting`, and one HTTPS host (`secure.ssa.gov`). The extension waits in memory for the exact visible heading **Return to Saved Application Process**, associates the exact SSN and re-entry labels through label/for, table, and adjacent container relationships, then requires one visible, enabled, writable input for each. It supports text, password and telephone fields, uses the native setter, dispatches input/change, verifies both values, and clears both values on failure. It clicks only one unique same-origin **Return to Saved Application Process** control after the starting Terms URL; it never clicks the Terms Next button or the identity-page Next button. `externally_connectable` accepts only the supported top-level Toolkit pages and the exact two-value launch shape. There is no storage, cookie, content-script, logging, analytics, or third-party service. The field controls are synthetic-tested, but live SSA markup has not been verified; any changed or ambiguous page pauses.

Only synthetic tests have been run; the live SSA flow and markup have not been verified by an automated browser test. A launch session is bound to one Toolkit tab and one SSA tab, times out after five minutes, and clears on reload, account change/logout, tab close, extension disconnect, fill, or failure. The user completes Login.gov, ID.me, MFA, CAPTCHA, attestations, signatures, penalty-of-perjury confirmations, and final submission manually. Later SSA application fields remain unmapped and paused.

## Client-profile boundary

The synthetic-practice bridge remains separate and still requires a fictional-intake declaration. The live extension does not consume that profile or any other complete profile. Its only two values are derived from one ready SSN field and entered in a temporary re-entry field; both stay in memory and are cleared on every terminal path. Application answers are not mapped or transferred.
